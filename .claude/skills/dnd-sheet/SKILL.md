## Testing protocol

- **`node --check` on extracted `<script>` is UNRELIABLE** on this file (a `</script>` literal in a string truncates the extraction; brace-count deltas are noise). **Always verify edits by loading the page in Playwright**: `page.on("pageerror")` + `typeof compute === 'function'`. If an Edit looks balanced but the page breaks, `git diff` for an accidentally duplicated/dropped line.
- **Playwright = the PYTHON package** (`/opt/homebrew/bin/playwright`), not Node. Click `#intro-skip` to dismiss the welcome overlay. Wait ~3s after load for `#source-data` to parse into `DATA` before probing spell renders.
- **Never `--headless=old`** (renders `<style>` as body text; `--dump-dom` can deadlock for an hour). macOS has no `timeout` binary (use `gtimeout` or a background poll). Prefer the browser-render skill or Playwright `evaluate()` + screenshots. Hung render: kill the Chrome chain on `user-data-dir=/tmp/render-e` + rm the lock dir.
- **Print-media FULL-PAGE screenshots paint blank/gray bands where content exists** (headless artifact on this file). Take ELEMENT screenshots or probe layout before diagnosing "blank page in print".
- **THE PRINT INVARIANT (three separate bugs, one law): nothing may mutate the Core/combat layout while `matchMedia('print').matches`.** Chrome's interactive print preview fires `focus` AND `resize` mid-print; any handler (`_ucsAfterPrint`, `fitDefenses`, `_ucsSync`→`activate()`) that reacts by relocating/resizing Core content blanks the first printed sheet. The structural guard now lives on the mutation itself: `activate()` early-returns while print media matches; `fitDefenses` clears its inline heights + skips scheduling while printing; `_ucsAfterPrint` early-returns while still printing. **Audit any new resize/focus/ResizeObserver-driven layout code for a print guard.** Repro seam (deterministic ~40s): `emulate_media('print')` → dispatch `beforeprint` → dispatch `focus`+`resize` ~5× → assert `body.ucs-layout` stays false and `#page-core` holds 0 `template.ucs-ph` / >1 `.card`. `page.pdf()` does NOT reproduce these (no interactive preview) but IS the discriminator for pagination bugs (extra blank first sheet).
- **PDF baseline for a blank sheet: 8 pages (1300px viewport).** Don't chase "missing pages" against remembered numbers -- render the pre-change commit and the current file in the same run and diff. GOTCHA: never call `emulate_media('screen')` before `page.pdf()` (it overrides pdf's print emulation and silently renders the dashboard -- looks like a regression, is a test artifact).
- **Theme preview:** copy index.html and swap `const DEFAULT_THEME = "ucs"` → target id; `let darkMode = prefBool(DARK_KEY)` → `true` for dark.
- **Headless seams:** hand-pushed `asiChoices` are wiped by `compute()→syncAsiSlots()` without a class -- set `#classlevel='Fighter 4'` first. Class-resource Limited rows come from `fillLimitedFeatures` at generation, not `refreshLimitedFeatures` -- seed them. Write-in spell rows hold the name in an INPUT VALUE (`input.sp-name`). A headless wizard sheet needs `spellMaxByInst[0]=9` + `spellEntriesOf(0)[L]` rows. `#armorsel` is populated from EQUIPPED INVENTORY -- setting `.value='Chain Mail'` on a blank sheet silently no-ops (append a real `<option>` or drive the add+equip path; read `armorByName(sel.value)` BEFORE compute). `speedBase` is null on a blank sheet → speed assertions are vacuous; set it. `DATA` is a plain script-scoped `let`, NOT a Proxy and NOT on `window` -- probe via functions or `typeof DATA`, never `window.DATA`.
- **Any viewport <820px flips `html.mobile`, which changes the ENTIRE print path** and prevents UCS activation -- print-CSS edits then "don't take" in probes but work in real prints. ALWAYS probe print at a wide viewport (1300). Also `html.mobile` is ON during every real print (paper width < 820) -- write mobile print rules accordingly.
- **For any animation/motion feature, also test a `reduced_motion="reduce"` context** -- Alex's Mac has macOS Reduce Motion ON and headless doesn't inherit it (this shipped two broken dice defaults).
- **Verify visual styles by COMPUTED value or rendered pixels, never the inline style you just set** (a CSS `!important` rule can override it; three "passing" portrait fixes shipped broken this way). Verify centering with screenshots, not rects (glyph ink can be off-center inside a centered box).
- **`position:fixed` elements have `offsetParent === null` ALWAYS** -- never use offsetParent for visibility/liveness (bit the dice-rail collider AND the prep-stat chip). Gate on computed `display` or a stable never-detached reference.

## Keep app CODE copyright-clean (load-bearing)

Alex may one day sell/distribute the sheet. **The baked `#source-data` blob is the ONLY place copyrighted content may live.** Null it → what's left must be a clean app (verified: ~13.3MB → ~2.85MB with a graceful "load a sourcebook" prompt).

- Never hardcode WotC TEXT into app JS. **STANDING RULE (2026-07-17): ALL rules text is VERBATIM from `#source-data`; only logic in app code.** Fully enforced since 2.135.0 (`CONDITIONS`/`TCE_RULES`/`SPELL_CHANGES` hold mechanics only; baked maps `conditionText` + `tceText` with readers `condText`/`tceText` beside `awText`, all falling back per-key to the baked blob via `bakedTextMap()`). App-BEHAVIOR text (UI hints) stays in code. "Spell Versatility" was UA-only, never in TCE -- don't re-add that toggle.
- **Names + mechanics + formulas are NOT copyrightable** -- hand-coded registries (`FEAT_SPELLS`, `FEAT_SKILLS`, `FEAT_SENSES`, `FEAT_INIT`, `FEAT_SPEED`, `FEATURE_ATTACKS`, `LIMITED_RESOURCES`, `ELSEWHERE_ITEMS`, `SPELL_CHANGES`, `TCE_RULES`, `ATTUNE_ALL_NAMES`, `AW_PROPS`, `DEF_ITEM_SPECIAL`, `EXTRA_SPELL_DC_ITEMS`, `REPEATABLE_FEATS`…) live in app JS and survive a rebake.
- New content type → route its TEXT through `#source-data` + a loader.
- WotC trade dress (Classic art) is fine -- Alex's call, sole judge of what ships; do NOT moralize about committing WotC data.

## Architecture / where things live

- **Unified source model (`DATA.sources`).** All three source paths (5etools batch, "Import files", homebrew) unify into `DATA.sources = [{id, name, kind:"5etools"|"file"|"homebrew", enabled, priority, data}]`. Helpers near `rebuildFromRaw`: `SRC_KINDS`, `srcId`, `hbBagsToData`, `migrateToSources` (folds legacy `_meta.raw` + homebrew, runs at load), `rebuildFromSources()` (the live merge, replaced `rebuildFromRaw()` calls), `tagSourcesFromRaw`. **Coexist+tag:** `mergeBook(into,add,name,opts)` stamps `_src`/`_srcName`; a `_coex` entity (imported/homebrew) keys on name+src so same-name entries from different sources COEXIST; plain official entities key on name (reprints dedup). `resolveEnt(list,name,src)` resolves a pick to its exact entity. `optLabel(x)` = "Name · Source" for background/feat/spell pickers. **The RACE list shows BARE NAMES** (`renderRaceList`, 2.158.2) with the source in `renderRaceDetail`'s `.wiz-cd-head`; it falls back to `optLabel` only when two loaded sources define the same name (nothing collides in the shipped 130). `#wiz-race` is a HIDDEN value-holder select -- its option text never displays, don't "fix" it. RACE is wired end-to-end by (name,src): hidden `#race-src`, `data-src` on list buttons, `wizRace()`/`applyRace` resolve by src. **Bake/persist STRIP `DATA.sources`** (rebuilt at load) -- never bake it. **ITEM source-choice is ONE gate, not a map re-key:** every item resolver reads homebrew through `hbActiveItems()`/`hbEnabledItem()` only; `#inv-prefer-official` (data-save) holds lc names the player chose official for (`preferOfficialSet`/`setPreferOfficial`); `hbPickerItems()` + `availableItemOptions()` show both entries for a colliding name; a chosen homebrew item may OVERRIDE official AC/DC on collision. `_meta.raw` + `SOURCES_RAW_KEY` still exist during the transition.
- **Storage = IndexedDB** (`dnd-sheet` db: chars, portraits, thumbnails) fronted by sync in-memory cache `_cs`. `SOURCES_KEY` + settings stay in localStorage. A file carrying baked characters partitions into `dnd-sheet-file-<hash>` (see BASE_KEY trap under Distribution).
- **Three data representations that DIVERGED -- not duplication to collapse:** (1) `build-data.py` = offline global baker (keep it; do NOT run a full rebuild to ship data -- it lags hand-patched fields and regresses; new data is spliced SURGICALLY into `#source-data` via Python string-insert); (2) the in-browser loader `etBook`/`mergeBook`/`bakeSourceData()`; (3) the shipped baked blob. Watch for drift BOTH ways: the JS loader can lag the baker, and the baked blob can carry stale PRE-RENDERED display strings from an older normalizer (e.g. class `prof.tools` are baked as display strings, not raw -- the tool picker `resolveToolChoices`/`TOOLPICK_RE` only cleans strings shaped exactly like live `etNormProf` output). **Baked-string fixes need a PAIR: correct the blob AND add a load-time migration for characters whose saved fields froze the bad text** (`migrateStaleToolProse` is the template -- and a stale-prose regex must match the text AS IT FROZE post-picker, pulled from real user data, not the pristine form). Note the blob carries the flattened `classes` array TWICE -- patch with replace-all. **`_meta.raw` (keyed by book NAME, not code) is a second, often HEALTHIER copy of every loaded book's extract -- diff it against the merged top-level collections before assuming data is absent.** That's how the 8 orphaned cross-book subclasses were found: extracted, stored in `raw[book].subclasses`, never attached. `build_classes()` returns `(classes, subclasses, subAug)` since 2026-08-10 -- it pools ALL class files and keys subclasses by className, because a book routinely adds a subclass to a class it doesn't define and 5etools splits class/subclass/feature across per-class files. Verify any baker change by diffing its `classes` output against `git show HEAD:build-data.py` for PHB + TCE + a define-nothing book, then diff its subclass objects against the shipped blob (they should be byte-identical -- that's the two-representations agreement check).
- **Byte-safe blob edit technique (ANY surgical `#source-data` change):** `json.loads` the blob, mutate, re-dump with `json.dumps(d, ensure_ascii=False, separators=(',',':'))` -- round-trips byte-identical so only changed values diff. To reproduce baked text formatting, import `build-data.py` and call its `entries_to_text`. The Edit tool fights this 13MB file (and SOH `\x01` separators can't be matched) -- use verified Python replaces for blob/version edits.

- **Overlaid controls CLIP the input they sit on** -- the symptom looks like occlusion but the fix is the CONTENT BOX (padding); the oracle is `input.scrollWidth > input.clientWidth`, not rect intersection. ## Design taste (this app only)

- **Flat / sharp:** square corners, no shadows, hairline borders, flat colors. D&D-sheet-ONLY -- don't generalize to Alex's other apps.
- **ANY light-tinted state class needs a `body.dark` twin** or dark mode goes white-on-white; measure contrast in BOTH modes. The dark accent is a LIGHT gold -- accent-filled controls need near-black ink in dark (white measures ~1.4:1). Use `--accent` for pressed/active states, not green (green = advantage/Heal here).
- **No emoji as icons** -- inline SVG with `currentColor`; icon source iconstash.io. The Cast button exists in TWO places (slot button + scroll render) that must stay in sync; icons go INSIDE the button (name readers use firstChild).
- **Logo/favicon = minimalist d20**, three surfaces generated FROM the favicon SVG (toolbar inline SVG, `<head>` data-URI favicon with a prefers-color-scheme swap so it survives dark tabs, PWA PNGs + a maskable variant refit to the safe circle).
